# Exprsn Platform documentation site

A fully self-contained, offline-capable static documentation site. No CDN
scripts, no external fonts, no network requests beyond same-origin fetches of
local files.

## Layout

```
docs/
  index.html              Landing page: service cards + Markdown guide cards
  setup-wizard.html       Setup wizard (npm run setup) + first-run flow
  exprsn-ca.html          Hand-written service pages
  exprsn-auth.html
  exprsn-timeline.html
  exprsn-prefetch.html
  exprsn-cortex.html
  database-model.html     Data-layer reference (all 14 module schemas)
  platform-model.html     Mermaid architecture diagrams
  glossary.html           Term definitions
  viewer.html             Markdown viewer (?doc=<id>, TOC sidebar)
  runbooks/               operational how-tos (living)
    secrets-and-rotation.md
    calendar-contacts-subscriptions.md
  plans/                  design/implementation plans, mostly delivered
    groups-frontend.md    Groups SPA expansion (implemented 2026-06-28)
    groups-admin.md       Admin-console Groups section (implemented 2026-06-28)
    plugins-plan.md       Flag-gated plugin system design
    plugins-decisions.md  GENERATED by `npm run plan:plugins` — do not hand-edit
    lowcode-clarifications.md  GENERATED by `scripts/lowcode-clarify.js` — do not hand-edit
  reports/                point-in-time audits and closed-out lists
    admin-interface.md    Endpoint → admin-UI mapping (2026-06-22)
    admin-improvements.md Admin frontend improvement notes
    todo-archive.md       Closed-out to-do list (shipped 2026-07-02)
  assets/
    docs.css              Shared stylesheet (incl. viewer/markdown styles)
    markdown.js           Vanilla-JS Markdown renderer (no dependencies)
    manifest.js           Doc manifest — assigns window.EXPRSN_DOCS_MANIFEST
```

The Markdown viewer surfaces the repo's living documents (`README.md`,
`ARCHITECTURE.md`, `API_SURFACE.md`, `STATUS.md`, `CLAUDE.md`) plus everything
under `docs/plans/`, `docs/reports/`, and `docs/runbooks/`. The list of
documents lives in `assets/manifest.js`; each entry is
`{ id, title, description, path }` with `path` relative to the **repo root**.
To add a document, add an entry there — nothing else to build.

Two path shapes are servable: a single-segment repo-root file (which also needs
its own bind mount in the nginx service's `docker-compose.yml` volumes) or
anything under `docs/` (already covered by the `./docs` mount). Files elsewhere
— `sprints/**`, for instance — fall through to the SPA and would render
`index.html` as Markdown, so they are deliberately not listed.

## Serving the site

The viewer fetches Markdown files with `fetch()`, so the site must be served
over HTTP. From the **repo root** (recommended — all documents reachable):

```bash
cd /path/to/exprsn-platform
python3 -m http.server 8000
# open http://localhost:8000/docs/
```

Serving from `docs/` also works for the HTML pages and the runbooks, but the
repo-root Markdown files (`ARCHITECTURE.md`, `STATUS.md`, ...) are then outside
the server root and the viewer will show a fetch error for them:

```bash
cd docs && python3 -m http.server 8000
# open http://localhost:8000/
```

The viewer resolves each manifest path against both roots automatically
(`../<path>` first, then the `docs/`-stripped path), so no configuration is
needed either way.

## file:// limitation

Opening the pages directly from disk (`file://...`) renders the hand-written
HTML pages fine, but the Markdown viewer cannot load documents: browsers block
`fetch()` of local files under the `file://` origin (CORS). The viewer detects
the failure and shows instructions. Use a local HTTP server as above.
