Modeling principles

Each module owns its schema and never declares foreign keys into another module's schema. Cross-module references (a Timeline post's userId, a Prefetch job's user_id) are logical UUID references resolved through service APIs or IPC, not database constraints. Within a schema, conventional Sequelize associations and FK constraints apply. Several modules use soft deletes (a deleted flag) instead of row removal, and the CA's audit log is append-only with a hash chain.

Known gap (STATUS.md #1): raw migrations with unqualified table names can land in public instead of the module schema. Schema-qualify table names or set a searchPath when touching migrations.
