decide them. The sprint is shaped so that none of them blocks the critical path.

1. **BUG-081: how to restore the lint gate.** All 6,323 lint errors on `main`
   are in code imported by the 2026-08-10 unrelated-histories merge (`89ff0ef`):
   the 22 `src/exprsn-*` trees plus `src/shared/`. The platform's own `src/`
   dirs and `services/` lint clean. Options: (a) remove the imported trees from
   the repo (they are not part of the 14-module registry); (b) move them out of

   (c) exclude them from lint explicitly. **Recommendation: (a) or (b).** Code
   that isn't part of the platform shouldn't sit under the gateway's `src/`, and
   both options leave the lint rules themselves unchanged. Note that
   `docs/plans/Design.md` names `src/exprsn-dbadmin` as the predecessor of the
   planned DB editor, so keep or archive that one deliberately.

   rolled three cycles. Either schedule the systems-architect sign-off this
   cycle (the gate is cheap) or formally park FEAT-078 → FEAT-079 and FEAT-093's
   query-time-embedding path, and say so in the backlog. Not on this sprint's
   critical path either way.
3. **BUG-080: ADR §3 group exemption.** Should a *blocked* sender's live
   delivery into a **group** conversation be closed at the *send* side? That

   This sprint commits only the unambiguous half (per-recipient delivery
   filtering + the `edit:message` contact re-check), which is correct either way.

### Sprint-scope notes per ticket

- **BUG-081 (sr, S, FIRST).** Day-1 work once the owner picks an option above.
  Every PR is currently red on a required check, so nothing else in the sprint
  can show a trustworthy green until this lands. Done = `npm run lint` exits 0 on
  `main` and the CI **Lint** job passes. Do **not** weaken `.eslintrc.json` rules
  to get there. Also look at the **Tests** job, which is red on `main` too: it
  is documented as non-blocking, but `ci.yml` has no `continue-on-error`, so it
  shows as a failed check. Either make the non-blocking status real in the
  workflow or record the failing suites as tickets. Don't leave it ambiguous.
- **TASK-074 (PM + sr, S).** TASK-073's spec merged (PR #1, 2026-09-28), but its
  AC4 ("§14 prerequisites filed as follow-up tickets before build starts") is not
  met. File them grouped by module, and pull the four security-flavoured rows
  §14 already severity-tags (`/ca` socket admits unauthenticated clients;
  `adminGuard` ignores token roles; live lifecycle routes have no platform-admin
  override; vault `aiPolicyService` queries a non-existent `createdAt`) out as
  individual P1/P2 `BUG`s. Not code; it unblocks next cycle's admin-console build.
- **FEAT-082 (anchor, M–L).** C/B: **APPROVE-REDUCED** (scheduling in full;
  triggers reduced to the in-process `triggerAgent()` + the TASK-062 HMAC
  webhook, which is done). Invariants from the C/B: persist the original repeat
  options on the schedule row so repeatables can be removed exactly; keep
  `attempts: 1` (agent runs are non-idempotent); misfire policy is
  skip-not-backfill, documented; per-agent overlap guard; disabling an agent
  halts both fire paths and leaves **no orphan repeatable jobs**. Per-module
  event wiring stays out (FEAT-097). **dba Bull-repeatable glance is a COMMIT
  gate** (see Sign-offs). Interacts with close-out carry-in #7: worktree gateways
  share one Redis, so QA must run FEAT-082's schedule verification on an
  isolated queue prefix or the fires will be stolen by other workers.
- **BUG-080 (jr with sr review, S–M).** Fix the root cause: emit per recipient
  instead of broadcasting to the room. Skip sockets whose viewer has the sender in
  `contactPolicy.getSuppressedIds` (cache it per conversation). Covers all five
  events: `new:message`, `message:edited`, `new:reaction`, `read:receipt`, plus
  the missing participant check on `add:reaction` (`socket/index.js:509`).
  `edit:message` gets a contact re-check **regardless** of decision 3, because
  its content is new. The send-side group-block question waits for the owner.
- **BUG-076 (jr, S).** Auth failure must be a 401, never a 500, and must not
  reach Postgres with a non-UUID: validate the token-id shape before the CA
  lookup. Check whether other modules share the CA path and inherit the fix.
- **TASK-071 (dba, S, before TASK-072).** Cover `cortex`, `plugins`, `lowcode`,
  `prefetch` when their flags are on; report duplicate constraints (the query
  already exists in BUG-064's sweep). This is also the regression gate for
  BUG-071's ~380 accreted constraints, so BUG-071 should follow it next cycle.
- **TASK-072 (qa + dev pairing, M).** Separate opt-in `jest.integration.config.js`
  against an isolated DB; default `test:all` stays DB-less. Minimum coverage:
  `runAgentChain` `onEscalate`, `AgentRun` lifecycle, `runTask` /
  `assistantChatTurn` review + outbox writes. Keep `reviewKind.test.js`. Ideally
  FEAT-082's new persistence (schedule rows, `scheduled`-origin runs) lands
  inside this layer from day one rather than as a follow-up.

  the fan-out cost per send. Keep the suppression lookup cached per

  dropped or duplicated events) as well as the suppression itself.
