Overview

Exprsn-Auth is the platform's centralized identity provider. It handles local registration and login, social OAuth (Google, GitHub via Passport), multi-factor authentication (TOTP plus backup codes), session management, and password lifecycle. It is also a full OAuth2/OIDC provider — authorization-code flow with PKCE, token issuance/introspection/revocation, OIDC discovery and JWKS — plus SAML 2.0 SSO integration and LDAP / Active Directory configuration and directory sync. A multi-tenant RBAC model (organizations, groups, roles, permissions) governs authorization across the ecosystem.

As a platform module it exports { name, app, init } — JSON API only, no views, no listen(). Sessions are stored in Redis (connect-redis, key prefix exprsn:auth:sess:) when Redis is enabled, with an in-memory fallback for development only. CORS honors an explicit comma-separated allowlist in CORS_ORIGIN; unset means cross-origin requests are disabled — wildcards are never combined with credentials.

Security features

Rate limiting on sensitive endpoints; account lockout after repeated failed logins; bcrypt password hashing (12 rounds); mandatory email verification; hashed MFA backup codes; session cookies with httpOnly, secure, and sameSite; PKCE enforcement for public OAuth2 clients; SAML response signature validation; LDAP over TLS; audit logging of auth events; helmet security headers with a restricted CSP; strict CORS allowlisting (no wildcard with credentials).

A fail-closed development auth bypass exists platform-wide (DEV_BYPASS + secret header + loopback only + NODE_ENV=development). Its conditions must never be weakened.

Integration & key files

Auth depends on @exprsn/shared for its logger, error handlers (errorHandler, notFoundHandler), and Redis client init, and on the CA service for CA-token generation and validation (services/auth/src/services/caService.js; health surfaced at /auth/health/ca). Downstream, every other module's users authenticate against identities and tokens this service manages.
