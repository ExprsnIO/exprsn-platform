Overview

Exprsn-Prefetch is a read-acceleration layer for timelines. It proactively fetches user timelines from the Timeline service and caches them in tiered Redis stores (a 5-minute hot tier and a 15-minute warm tier), so feed reads can be served from cache instead of recomputing. Prefetching is driven by a Bull queue with priorities and retries, plus an activity-based strategy that periodically schedules prefetches for recently active users. The service records cache hit/miss and duration metrics in Redis and exposes extensive health endpoints, including Kubernetes-style readiness and liveness probes.

It never fetches user-supplied URLs — its only outbound calls go to the fixed, configured Timeline, CA, and Auth service URLs.

API endpoints

Paths are as reached through the gateway (prefix /prefetch). Auth is via CA tokens with permission checks; requireSelfOrAdmin means users may act only on their own timeline unless they hold admin.

PostgreSQL

The prefetch.prefetch_jobs table (UUID id, user_id, priority, status, result JSONB, timestamps) is created by scripts/migrate-postgres.js, but at runtime jobs live in the Redis-backed Bull queue; the table is provisioned for persistence/analytics and is not on the hot path.

Bull queue & worker

Single queue named prefetch (src/queues/prefetchQueue.js), job type timeline:

AspectValue
Concurrency100 (PREFETCH_JOB_CONCURRENCY)
Priorities1 = high, 2 = medium, 3 = low; job ID prefetch:{userId}:{timestamp}
Retries3 attempts, exponential backoff (2 s → 4 s → 8 s)
RetentionLast 100 completed / 50 failed jobs kept
Job flowFetch GET {TIMELINE_SERVICE_URL}/api/timeline/user/{userId}?limit={MAX_TIMELINE_SIZE} → cache by tier → record metrics

Public queue API: queuePrefetch, queueBatchPrefetch, getQueueStats, getFailedJobs, retryFailedJob, cleanQueue, pauseQueue, resumeQueue, closePrefetchQueue.

Scheduling: the module's init() starts a scheduler that runs the activity-based strategy every ACTIVITY_CHECK_INTERVAL (60 s default), enqueuing prefetches for recently active users. The standalone worker (src/worker.js) is a minimal alternative that runs the same strategy directly on an interval. Strategy flags: ENABLE_ACTIVITY_BASED (true), ENABLE_EVENT_TRIGGERED and ENABLE_PREDICTIVE (defined but unused in the current code).

Security

All API routes validate CA tokens via @exprsn/shared's validateCAToken with per-endpoint permission checks (read/write/delete) and requireSelfOrAdmin ownership enforcement. Outbound calls carry CA-issued service bearer tokens managed by a ServiceTokenCache (1 h expiry; on a 401/403 the cache is cleared and the request retried once). SSRF exposure is minimal: target URLs come only from hardcoded config keys (timeline, auth, ca) — unknown service names throw — and every outbound request has a timeout (10 s for timeline fetches, 3–5 s for health checks). Rate limits: 300 req/min global, 100 req/min on prefetch routes, 300 req/min on cache reads. Degradation is graceful: Redis failure makes readiness fail (503); Timeline/CA outages log, record metrics, and surface as warnings.
