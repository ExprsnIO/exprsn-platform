Platform & architecture

Ten microservices, consolidated into one process behind one HTTPS port.

Exprsn's originals — CA, auth, Spark, Nexus, FileVault, Vault, Timeline, Prefetch, Moderator, and Live — each ran as their own service on their own port. This is how they became one deployable, self-hostable platform.

Topology

One gateway, one socket server, one database

Everything is reached through a single Express app. Modules never open their own port, their own view engine, or their own static file mount.

            ┌──────────────────────── one HTTPS port (8443) ────────────────────────┐
   client → │  gateway (helmet/cors/compression) + single Socket.IO (/socket.io)     │
            │    /ca/*  /auth/*  /spark/*  …  /live/*   →  mounted module Express apps │
            │    namespaces: /ca /spark /timeline /live /vault /moderation …          │
            └───────────────────────────────────────────────────────────────────────┘
                      │                          │
              one Postgres db exprsn     one Redis instance
              schemas: ca, auth, spark…    (key-prefix / db-number isolation)

Only 8443 (HTTPS) is exposed publicly. An optional 8080 issues a 301 redirect to HTTPS and can be disabled entirely. Postgres, Redis, and search infrastructure stay on the loopback / private network — never reachable directly.

Module contract

Every module is a plain Express app that agrees to three rules

No listen(), no view engine, no static mounts, no setup wizard. A module hands the gateway an app, optionally attaches a Socket.IO namespace, and optionally runs async setup during boot. That's the entire interface.

  • Routes are reached at <prefix>/<internal-route>, e.g. /spark/api/conversations.
  • Modules are JSON APIs only — the front end lives entirely outside this repo.
  • Service-to-service calls use per-service HMAC tokens, not shared secrets.
services/<name>/index.js 
module.exports = {
  name,                     // module id, e.g. 'spark'
  app,                      // Express app/router — no listen(),
                             // no views, no static, no setup routes
  registerSockets(io) {},  // optional — attach this module's
                             // namespace(s) to the shared io
  async init(ctx) {},        // optional — db/redis/queue setup;
                             // MUST NOT listen. ctx = { config,
                             // logger, schema }
};

Data isolation

One database, real schema boundaries

Consolidation didn't mean flattening every module's tables into one namespace.

1

Single Postgres database, per-module schema

All modules share database exprsn, but each module's tables live in their own Postgres schema, set via Sequelize's define.schema — a Spark query can't accidentally touch Timeline's tables.

2

One shared Redis, namespaced keys

Cache, sessions, and Bull queues share a single Redis instance. Logical DB numbers and key prefixes (like Prefetch's prefetch: prefix) keep modules from colliding on the same keyspace.

3

Background workers stay separate

Bull queue workers for Timeline and Prefetch run as their own processes against the shared Postgres/Redis — the gateway only enqueues jobs, it never runs them inline.

Quick start

Running locally in six commands

Plain Node.js (CommonJS), Express 4, Sequelize 6, and Socket.IO 4 — nothing exotic to install beyond Postgres and Redis. The web client is a separate Vite + React SPA served by nginx, never by a backend module.

terminal 
# install deps + generate a dev TLS cert
npm install
npm run gen:certs

# configure, then create db + per-module schemas
cp .env.example .env
npm run db:bootstrap
npm run db:migrate

# start the gateway
npm start
# → https://localhost:8443
curl -k https://localhost:8443/health
