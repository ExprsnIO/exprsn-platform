Glossary

Terms used throughout the Exprsn Platform documentation, grouped by area.

Platform architecture

Gateway
The single edge Express app (src/gateway.js) that fronts every module: helmet/CORS/compression, aggregate /health, per-module mounts, a central error handler (returns a correlation ID, never leaks internals), and the one shared Socket.IO server.
Module
A formerly standalone microservice now loaded in-process. Each module's entry exports { name, app, registerSockets(io)?, init(ctx)? } — an Express app with no listen(), no views, no static assets. Modules are JSON APIs only.
Module registry
src/modules/registry.js — the canonical list of modules: name, mount prefix, Postgres schema, entry file, and Socket.IO namespace(s). Schema bootstrap, migrations, and gateway mounts all derive from it.
Mount prefix
The gateway path where a module is reachable. A module's internal /api/foo route is reached at <prefix>/api/foo, e.g. /timeline/api/posts.
Schema-per-module
Data isolation pattern: one Postgres database (exprsn) with a dedicated schema per module (ca, auth, timeline, prefetch, …), set via Sequelize's define.schema.
IPC (inter-process communication)
The platform's in-process event channel between modules. Example: the CA answers cert:validate and token:validate events; Timeline relays post:created/updated/deleted IPC events to its Socket.IO namespace.
HMAC service token
Service-to-service credential: X-Service-ID + X-Service-Token headers, where the token is HMAC-SHA256 over the service ID using SERVICE_TOKEN_SECRET. The unified process presents SERVICE_ID=platform.
@exprsn/shared
The shared utility package (auth/token middleware, role validation, error handling, rate limiting, audit logging). Two live copies exist — shared/ (the npm package) and services/shared/ (a relative-require copy) — and must be kept in sync.
DEV_BYPASS
A fail-closed development-only auth bypass requiring DEV_BYPASS, a secret header, a loopback source address, and NODE_ENV=development simultaneously. Its conditions must never be weakened.
Socket.IO namespace
A logical channel on the single shared Socket.IO server (path /socket.io). Modules attach their own namespaces, e.g. /ca and /timeline.
Bull queue
Redis-backed job queue library used for background work (fan-out, trending, indexing, notifications, prefetching). Queue workers run as separate processes from the gateway.
Sequelize
The ORM (v6) used by all modules for Postgres access, including model definitions, schema scoping, and migrations.

PKI & the CA service

CA (Certificate Authority)
An entity that issues and signs digital certificates. Exprsn-CA operates the platform's private CA hierarchy.
X.509 certificate
The standard format (RFC 5280) for public-key certificates, binding a subject identity to a public key, signed by an issuer.
Root / intermediate / entity certificate
The trust hierarchy: a self-signed root CA (20-year validity here) signs intermediates (10 years), which sign end-entity certificates (1 year) for users, servers, clients, and code signing.
CSR (Certificate Signing Request)
A signed request containing a public key and subject details, submitted to a CA for certificate issuance (POST /ca/api/certificates/csr).
SAN (Subject Alternative Name)
An X.509 extension listing additional identities (DNS names, emails, URIs) a certificate covers.
CRL (Certificate Revocation List)
A signed, periodically regenerated list of revoked certificate serials (RFC 5280 §5), distributed at /ca/crl/current.crl with a monotonically increasing CRL number.
OCSP (Online Certificate Status Protocol)
A real-time certificate status protocol (RFC 6960). The CA's responder answers DER-encoded requests at /ca/ocsp with signed good/revoked/unknown responses.
ACME
Automatic Certificate Management Environment (RFC 8555) — the protocol used by clients like certbot. Exprsn-CA has ACME data models and migrations in place; protocol handlers are pending.
CA token (Exprsn CA Token Specification v1.0)
The platform's signed bearer token: permission flags (read/write/append/delete/update), a resource binding (url/did/cid), an expiry model (time-, use-based, or persistent), a SHA-256 checksum, and an RSA-SHA256-PSS signature. Used as Authorization: Bearer … across modules.
Audit hash chain
Tamper-evidence scheme in the CA's audit log: each entry's entryHash covers the previous entry's hash (prevHash), so any retroactive edit breaks the chain. The chain is append-only.
PEM / DER
Certificate encodings: DER is binary ASN.1; PEM is Base64-encoded DER wrapped in -----BEGIN/END----- markers.
Fingerprint
SHA-256 digest of a certificate, used as a unique identifier.
RSA-SHA256-PSS
RSA signing with SHA-256 and the PSS padding scheme (PKCS#1 v2.1) — used for CA token signatures.
RBAC (Role-Based Access Control)
Authorization model in which permissions attach to roles, and roles to users or groups. Both CA and Auth implement RBAC.

Identity & the Auth service

OAuth2
Delegated-authorization framework. Exprsn-Auth is a full provider: authorization-code grant, refresh tokens, revocation, and introspection (RFC 7662).
PKCE
Proof Key for Code Exchange — an OAuth2 extension protecting the code flow for public clients via a code verifier/challenge pair. Enforced for public clients.
OIDC (OpenID Connect)
An identity layer on OAuth2: ID tokens, the UserInfo endpoint, and discovery at /.well-known/openid-configuration.
JWKS (JSON Web Key Set)
The published set of public keys (/.well-known/jwks.json) clients use to verify token signatures.
MFA / TOTP
Multi-factor authentication using Time-based One-Time Passwords (authenticator apps), enrolled via QR code, with hashed single-use backup codes.
SAML 2.0
XML-based enterprise SSO. Auth acts as a Service Provider (SP): metadata, IdP-initiated login, Assertion Consumer Service callback, single logout.
IdP / SP
Identity Provider (asserts who a user is) and Service Provider (consumes that assertion) in SSO flows.
LDAP / Active Directory sync
Directory integration: admin-configured connections that import and synchronize users and groups, one-shot or on a schedule.
Session store
Where session state lives — Redis (connect-redis, prefix exprsn:auth:sess:) in normal operation; in-memory only for development.
bcrypt
Adaptive password-hashing algorithm; Auth uses 12 rounds, CA defaults to 10.
Account lockout
Brute-force protection: repeated failed logins increment a counter and temporarily lock the account (failedLoginAttempts / lockedUntil).

Feeds, caching & background processing

Timeline / feed
An ordered stream of posts. The home feed is ranked (recency, engagement, relationship strength, media); user timelines are reverse-chronological.
Fan-out (on write)
Distributing a new post to each follower's timeline at write time — to Redis sorted sets for hot reads and to the database for durability — via the fanout Bull queue in batches of 100 followers.
Hot / warm cache tiers
Prefetch's Redis tiers: hot (DB 0, 5-minute TTL) for recently active users; warm (DB 1, 15-minute TTL) for everyone else. Reads check hot first, then warm.
Cache invalidation
Removing stale cached timelines — explicitly (DELETE /prefetch/api/cache/:userId/timeline) or via fan-out cache-invalidation jobs.
Activity-based prefetching
Prefetch strategy that periodically (every 60 s by default) enqueues timeline prefetches for recently active users, so their next feed read is a cache hit.
Cursor pagination
Paging with an opaque (Base64) cursor pointing at the last seen item, more stable than offsets for fast-moving feeds. Timeline supports both.
Soft delete
Marking a row deleted (a deleted flag) instead of removing it, preserving referential integrity and history.
Trending score
A computed ranking (trendScore) over topics/hashtags based on 24-hour post and engagement counts, recalculated every 15 minutes.
ElasticSearch
Optional full-text search backend for posts (index exprsn_posts), kept current by the indexing queue; SQL search is the fallback.
Bluesky / AT Protocol
A decentralized social network protocol. Timeline syncs posts outward and ingests events via an HMAC-verified webhook; posts carry blueskyUri/blueskyDid/blueskyRkey.
DID
Decentralized Identifier — a portable, cryptographically verifiable identity string (used by Bluesky accounts and as a CA-token resource type).
Herald / Spark / FileVault / Nexus
Sibling platform modules: Herald delivers user notifications; Spark is real-time messaging; FileVault stores files/attachments; Nexus manages groups.
Readiness / liveness probes
Kubernetes-style health endpoints: liveness (process alive) vs. readiness (dependencies available — e.g. Prefetch returns 503 if Redis is down).
SSRF (Server-Side Request Forgery)
An attack tricking a server into fetching attacker-chosen URLs. Prefetch mitigates it by only calling fixed, configured service URLs with timeouts.
Webhook
An inbound HTTP callback from an external system (e.g. Bluesky PDS events), authenticated here with an HMAC-SHA256 signature.
