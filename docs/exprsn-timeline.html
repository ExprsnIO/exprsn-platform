Overview

Exprsn-Timeline powers the platform's social feed: post creation and lifecycle, personalized/global/explore/trending timelines, interactions (likes, comments, reposts, bookmarks, follows), curated lists, search (ElasticSearch with SQL fallback), file attachments via FileVault, and federation with Bluesky (AT Protocol) through webhooks. Heavy work — fan-out to followers, trending calculation, search indexing, notifications — is deferred to Bull queues processed by a separate worker process.

All HTTP routes authenticate with a CA token (Authorization: Bearer <token>) validated against the CA service; permission flags (read/write/update/delete) on the token gate each endpoint.

Feed & fan-out architecture

Feed ranking (feedService.js): the home feed combines posts from followed users plus the caller's own, scored by recency (time decay), engagement (likes/reposts/comments), relationship strength, and media presence. The explore feed surfaces popular posts from the last 7 days; user timelines are plain reverse-chronological. Pagination supports Base64 cursors and offsets.

Fan-out on write (fanoutService.js): when a post is created, a post-fanout job distributes it to every active follower — written both to Redis (sorted set timeline:{userId}, scores = timestamps, TTL 5 min, capped at 100 posts) for hot reads and to the database for durable timeline reconstruction, in batches of 100 followers. Deletion enqueues post-removal; cache invalidation is also job-driven.

Post-creation flow: create record → extract entities (hashtags, mentions, URLs) → enqueue fanout.post-fanout, trending.hashtag-extraction, indexing.post-index → notify Bluesky asynchronously → broadcast new:post on the /timeline Socket.IO namespace.

Bull queues & worker

Defined in src/config/queue.js; processed by src/worker.js (run separately: node services/timeline/src/worker.js). The worker also schedules recurring jobs: trending-update every 15 minutes and trending-cleanup daily at 3 AM.

QueueConcurrencyRetryJobs
fanout (high priority)103 attempts, exponential (2 s)post-fanout (distribute to followers), post-removal, cache-invalidation
trending (medium)52 attempts, fixed (5 s)hashtag-extraction, trending-update (cron */15 min), trending-cleanup (daily 3 AM)
indexing (low)33 attempts, exponential (3 s)post-index (index/update/delete in ElasticSearch), bulk-reindex
notifications (high)205 attempts, exponential (1 s)notification, batch-notification → Herald; types: like, repost, comment, reply, mention, follow
