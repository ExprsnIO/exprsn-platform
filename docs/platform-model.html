Platform architecture

One Node.js process serves all ten modules behind a single HTTPS port. The gateway mounts each module at its prefix from src/modules/registry.js and owns the single Socket.IO server; Bull workers run as separate processes. Documented modules are highlighted.

Request & authentication flow

How an API call is authenticated. User traffic carries a CA token; module-to-module traffic uses HMAC service tokens and flows back through the gateway via *_SERVICE_URL (all pointing at https://localhost:8443/<module>).

sequenceDiagram
    autonumber
    participant C as Client
    participant G as Gateway (port 8443)
    participant M as Module (e.g. Timeline)
    participant CA as CA module

    C->>G: HTTPS request
Authorization: Bearer <CA token>
    G->>M: route by prefix (/timeline/api/…)
    M->>CA: validate token
(POST /ca/api/tokens/validate or IPC token:validate)
    CA->>CA: check status, RSA-PSS signature,
permissions, resource — Redis cache 300s
    CA-->>M: { valid, userId, permissions }
    alt token valid + permission present
        M->>M: handle request (Sequelize → module schema)
        M-->>C: 200 JSON
    else invalid / insufficient
        M-->>C: 401 / 403 JSON
    end

Post-creation flow (Timeline)

Write path with fan-out on write: synchronous persistence, asynchronous distribution.

sequenceDiagram
    autonumber
    participant C as Client
    participant T as Timeline module
    participant DB as Postgres (timeline schema)
    participant Q as Bull queues (Redis)
    participant W as Timeline worker
    participant H as Herald
    participant S as Socket.IO /timeline

    C->>T: POST /timeline/api/posts
    T->>T: sanitize, extract hashtags/mentions/URLs
    T->>DB: INSERT posts row
    T->>Q: enqueue post-fanout, hashtag-extraction, post-index
    T->>S: emit new:post to timeline:global
    T-->>C: 201 created
    W->>Q: consume post-fanout
    W->>DB: fan-out rows (batches of 100 followers)
    W->>Q: write timeline:{userId} sorted sets (TTL 5 min)
    W->>H: notification jobs (like/comment/repost/mention/follow)

Cached feed read (Prefetch)

Read acceleration: hot tier first, warm fallback, queued refresh on miss.

sequenceDiagram
    autonumber
    participant C as Client
    participant P as Prefetch module
    participant R0 as Redis hot (DB 0, 5 min)
    participant R1 as Redis warm (DB 1, 15 min)
    participant Q as Bull queue prefetch
    participant T as Timeline module

    C->>P: GET /prefetch/api/cache/:userId
    P->>R0: GET timeline:{userId}
    alt hot hit
        R0-->>P: cached timeline
        P-->>C: 200 (tier: hot)
    else hot miss
        P->>R1: GET timeline:{userId}
        alt warm hit
            R1-->>P: cached timeline
            P-->>C: 200 (tier: warm)
        else full miss
            P-->>C: 404 not cached
            C->>P: POST /prefetch/api/prefetch/schedule/:userId
            P->>Q: enqueue timeline job (priority, 3 retries)
            Q->>T: GET /api/timeline/user/:userId?limit=100
            T-->>Q: posts
            Q->>R0: SET timeline:{userId} (tier by priority)
        end
    end
